# Pharmacy System

A React/Vite frontend, PHP 8.1+ REST API, and MySQL database. This project supports local Windows/XAMPP development and Apache PHP shared hosting. Read [PROJECT_PROGRESS.md](PROJECT_PROGRESS.md) before using it with real pharmacy, customer, or financial records; production gaps remain.

## Run locally on Windows

### First-time setup

1. Install XAMPP with PHP and MySQL, plus Node.js LTS.
2. Open XAMPP Control Panel and start **MySQL**.
3. Create a local database named `pharmacy` in phpMyAdmin and import `database/schema.sql` if this is a fresh database. Do not import it over a database containing data.
4. Copy `.env.example` to `.env` in the repository root. Set `DB_NAME`, `DB_USER`, and `DB_PASSWORD` to match your local MySQL setup. Keep `.env` private.
5. Install PHP dependencies from the repository root:

   ```powershell
   cd backend
   composer install --no-dev
   cd ..
   ```

   If Composer is not installed, install it or prepare `backend/vendor` before running the API.
6. Install the frontend packages:

   ```powershell
   cd frontend
   npm install
   ```

### Start the app

1. In a terminal at the repository root, start the PHP API and leave that terminal open:

   ```powershell
   php -S 127.0.0.1:8000 -t backend/public backend/router.php
   ```

   If PHP is not on PATH, use XAMPP's executable, for example `C:\xampp\php\php.exe -S 127.0.0.1:8000 -t backend/public backend/router.php`.
2. In another terminal, start the frontend and leave it open:

   ```powershell
   cd frontend
   npm run dev -- --host 127.0.0.1
   ```

3. Open <http://127.0.0.1:5173>. The API health check is <http://127.0.0.1:8000/api/health>; it should return `{"ok":true,"service":"pharmacy-api"}`.
4. Sign in with the existing Administrator account, or use the first-run setup screen if there is no Administrator yet. Customer pages are `/products` and `/customer`.

Stop either server with **Ctrl+C**. Stop MySQL in the XAMPP panel when finished.

## Deploy to Roadline shared hosting

The production setup uses a static React build plus the PHP API. Do not run the Vite development server on shared hosting. Roadline's exact panel features depend on your plan, so confirm the document root, PHP extensions, and API layout with Roadline support.

### Build on your computer

1. Confirm with Roadline that your plan supports PHP 8.1+ and `pdo_mysql`, `curl`, `fileinfo`, `mbstring`, and `openssl`; ask whether you have cPanel, SSH/Composer, HTTPS, MySQL, and can set a domain/subdomain document root to `backend/public`.
2. Create a production MySQL database and restricted database user using the hosting panel. Import `database/schema.sql` once, then note the exact DB host, database name, username, and password.
3. Install PHP dependencies from the repository root:

   ```powershell
   cd backend
   composer install --no-dev --optimize-autoloader
   cd ..
   ```

4. Confirm `frontend/.env.production` has the live API URL. It is currently set to `https://kisikypharmacy.com/api`; change it if Roadline hosts the API on another domain or path. The production build uses this URL, and Apache serves client-side React routes from `index.html` using `frontend/public/.htaccess` (which is included in `dist`). Build the site:

   ```powershell
   cd frontend
   npm install
   npm run build
   ```

   Upload the **contents** of `frontend/dist`, not the frontend source folder.

### Upload and configure

1. Enable HTTPS/SSL for the website and API host.
2. Upload the contents of `frontend/dist` to the website document root (often `public_html`; confirm with Roadline).
3. Place the backend in a private directory outside the public document root if possible. Point the API domain/subdomain document root at `backend/public` (the folder containing `index.php` and `.htaccess`). Keep `backend/config`, `backend/routes`, `backend/src`, `.env`, and database files inaccessible from the web. If Roadline cannot point an API document root at that folder, ask support for their secure PHP API layout before placing backend files under `public_html`.
4. Upload `backend/vendor` generated by Composer. If SSH/Composer is available on the host, upload `backend/composer.json` and `backend/composer.lock` and run `composer install --no-dev --optimize-autoloader` in the backend folder instead.
5. Create the production `.env` in the project root, one directory above `backend/` (the location expected by the backend). Do not publish or commit it. Set values using the exact credentials Roadline provides:

   ```dotenv
   APP_ENV=production
   APP_URL=https://your-domain.example
   FRONTEND_ORIGIN=https://your-domain.example
   SESSION_NAME=use_a_long_random_name
   DB_HOST=host_value_from_Roadline
   DB_PORT=3306
   DB_NAME=hosting_database_name
   DB_USER=hosting_database_user
   DB_PASSWORD=hosting_database_password
   ```

   Shared hosts often prefix database names and usernames with your hosting account name. Add SMTP/SMS values here when ready; never put those credentials in frontend variables.
6. Ensure `backend/storage` and `backend/public/uploads` are writable by PHP with the minimum permissions Roadline recommends. Keep `backend/storage` private; it contains error logs. Do not use `777` permissions.
7. Ensure `FRONTEND_ORIGIN` matches the website's exact HTTPS origin. The frontend build's `VITE_API_URL` must match the live HTTPS API URL. When website and API use separate subdomains, both need HTTPS; the PHP API must allow credentialed CORS and session cookies for the frontend origin.
8. Ask Roadline to confirm Apache `mod_rewrite` and `.htaccess` overrides are enabled. The included frontend rule serves React routes such as `/products` from `index.html` and excludes `/api` so those requests reach PHP. Configure the host so `/api` is actually mapped to the backend's `public` directory or API host.
9. If the database has no Administrator, use the app's first-run setup screen and create a unique password of at least 12 characters. The setup route should refuse creating another administrator after setup is complete.
10. Open `https://your-api-host/api/health`, then verify sign-in, customer registration, catalogue loading, and important staff actions before using real records. Check the hosting PHP error log if an API endpoint returns HTTP 500.

### Ask Roadline support

- Does my plan support PHP 8.1+ and `pdo_mysql`, `curl`, `fileinfo`, `mbstring`, and `openssl`?
- Can I point an API subdomain's document root at a folder's `public` directory?
- Are Apache `mod_rewrite` and `.htaccess` overrides enabled?
- What MySQL host and PHP upload/session limits should I use?
- Is SSH/Composer available, or should I upload the Composer `vendor` folder?
- Can the PHP API use HTTPS sessions with credentialed requests from my website domain?
